# Shared scorecards: two signatures on one device

The designated scorer can choose **Both parties sign on this device** after finishing and uploading the match. Both representatives review the totals and sign, in turn, with their own printed names. The existing separate-account **Review and agree scores** route remains available. Cancelling either signature leaves agreements unchanged; signatures are saved together, online, against the reviewed server version.

Signing acknowledges the scorecard. It does not submit the competition result, confirm it, or advance the winner. The existing submission action follows acknowledgement; a Club Admin / Competition Secretary still confirms the pending result separately. A marker may collect the signatures but still cannot submit as a player. Existing player and Admin submission permissions remain unchanged.

Signed cards can be viewed/exported from the shared screen's PDF button. The signatures also cache against the matching local upload revision for later viewing. Corrections, reopening and Admin return invalidate signatures and agreements. Signature evidence, uploader, server time, version and totals remain in the private audit events. Stale signing, non-owner signing, malformed signatures and anonymous access are rejected. Routine repeat uploads ignore signature fields and preserve server-captured evidence; genuine document changes clear it.

Database: additive agreement method/name columns and a new authenticated signing RPC, with existing authorization checks. No direct table grants. Shared state and result guard accept either valid player-account agreements or signature acknowledgements captured by the designated scorer. Existing fixture/result/booking permissions are preserved. Recovery can disable new captures using `scripts/recovery_shared_same_device_signatures.sql`; keep additive columns, guard and evidence while signed cards exist. Original live definitions are recorded in `before-functions.json` for reviewed recovery, not blind replay.
