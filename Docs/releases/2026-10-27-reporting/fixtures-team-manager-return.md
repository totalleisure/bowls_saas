# Fixtures list return from Team Manager

Follow-up to fixture-list-return.md. That amendment covered DiaryListScreen but missed the separate FixturesScreen used for Fixtures/Member Fixtures. FixturesScreen called its full loader only when Fixture Details returned true. Details sets its change flag after Team Manager refresh even when the user only inspected the team, explaining the reported direct-return versus nested-return difference.

FixturesScreen now retains an explicit scroll controller and a Club/mode-scoped storage key. A changed details return fetches only that fixture, reusing the exact full-list projection and Club, member-booking/captain and future-date restrictions. It replaces/removes that entry, sorts it by date and ID, and preserves the bounded current scroll offset. It does not reload permissions, Club branding or the fixture collection, or replace the list with a loading spinner. Unchanged returns keep existing behaviour and make no fixture lookup. Failed single-item requests leave existing cards in place with a retry message. Create, Show/Hide Past and manual Refresh retain their explicit full-reload behaviour.

New regression tests exercise two sequential fixture visits: first a direct details return without changes, then another fixture through a Team Manager route and back through changed Details. Changed, deleted and failed lookup cases retain offset and verify exactly one initial collection query plus one ID-scoped query, preserving member-booking scope. Together with the Diary List return suite, 9 tests passed in staging and the same 9 in production. Shared Dart source comparison passed. Existing unused import/field notices in FixturesScreen remain; no new functional analyser errors.

Promoted only FixturesScreen and the new regression test after reviewing the production/source difference. No database, Edge function, store release, commit, push or version change. Restart the local Flutter App to review the correction.
