# iOS release handoff — 1.6.6 (32)

1. Use the existing production Git checkout on the signing Mac. Run `git status` first; retain any local work and do not reset/clean it. Fetch origin and switch to `codex/release-1.6.6-32`, tracking the same remote branch, then use `git pull --ff-only`. This branch is the reviewed release candidate; pulling release/1.6.5 alone will not obtain it.
2. Check the latest commit and pubspec.yaml (1.6.6+32). Production entry point is lib/main.dart; bundle ID is com.totalleisure.bowlssaas. Retain the Mac's existing ignored production lib/secrets.dart configuration, Apple signing team and certificates. Do not use staging_main.dart or transfer staging credentials. Secrets/signing files are deliberately not committed; a fresh clone needs the existing production configuration restored locally.
3. Use the verified Flutter release tooling (Windows validation used Flutter 3.44.9 / Dart 3.12.2). On macOS with Xcode/CocoaPods installed, run `bash Docs/releases/1.6.6-32/build-ios-release.sh` from the Git project root. It builds the archive/IPA and does not upload it. Generated settings must be rebuilt on the Mac. pod install is required because existing Podfile.lock checksum metadata is stale; inspect its changes.
4. In Xcode validate the archive, version 1.6.6, build 32, production identity, entitlements and signing. Confirm build 32 is available for use in App Store Connect; the existing internal build 31 remains unchanged. If 32 has already been uploaded, a new unique build number is required.
5. Upload the validated IPA/archive through Xcode Organizer or Transporter. Assign 1.6.6 (32) to internal TestFlight, using testflight-notes.txt for acceptance. Exercise calendar updates/cancellations on the actual phone and retain any duplicate entries for diagnosis. No silent update guarantee is made.
6. After acceptance, prepare App Store version 1.6.6 with app-store-whats-new.txt and select the same tested build 32. Review the metadata and any review/export-compliance questions in App Store Connect, then submit for review. Submission and public release have not been performed by this task.
