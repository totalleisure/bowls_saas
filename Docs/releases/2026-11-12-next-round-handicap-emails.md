# Next-round handicap emails

Next-round messages for `team_difference` competitions show every player's individual handicap, each entry's combined handicap, and both calculated starting scores, oriented as Your team / Opponents for each recipient. Totals are calculated from frozen individual values, not the cached entry total. Signed and zero values are preserved; incomplete values show `not recorded` and `awaiting complete handicaps`. Non-handicap email content is unchanged. User text is escaped by the shared HTML renderer.

Nineteen focused email tests pass in staging and production source, including opponent perspective, equal/signed/missing values, recipient restrictions, HTML escaping and global 20/minute handling. The staging deployed worker was downloaded and compared, then rendered the actual Handicap Test Tournament semi-final snapshot locally: combined 20 versus 7, starting 0 versus 13. No test email or duplicate was sent. Existing sent messages are not requeued or changed.

The `competition-round-ready` worker is deployed in both environments; production is version 4, all eight deployed files verified against the reviewed bundle. Only the next-round formatter and optional HTML section changed. Worker authentication, staging's seven-address restriction, production recipient eligibility, queues, timers and transport remain unchanged. No schema change or Flutter update is needed for these future emails. Shared source files were aligned before promotion. The pre-update deployed worker snapshot is retained locally under `tmp/handicap-mail-prod-before` and `tmp/handicap-mail-before`; recovery is to redeploy those reviewed formatter/template files with the existing worker bundle, without replaying queue deliveries.
