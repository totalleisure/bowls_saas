# Admin confirmation resend and rink labels

Admins can open a member record and use **Resend confirmation email** beneath the account actions when the linked login email remains unconfirmed. The action checks status without sending, asks for confirmation showing the server-verified address, then uses the normal Auth signup resend flow. Confirmed/unlinked/captain-managed accounts offer no resend. Status failures remain visible with retry. Email changes remount the status control. Ordinary members do not receive this control.

The server verifies the signed-in user and active club administrator/platform administrator authority, active target membership and privileged-target restrictions consistent with existing password administration. It reads the login email server-side, rejects stale/mismatched addresses, refuses confirmed accounts, applies a one-minute cooldown and verifies the native confirmation-sent timestamp after sending. It does not reset passwords, confirm accounts directly or expose confirmation tokens. Both endpoint deployments require JWT authentication. Real email sending during this feature's tests was mocked; the earlier requested manual resend to Patricia is separate.

Normal rink cards and quick-booking timeline cards now include a distinct Fixture Label (team_name) on a second line. Existing type/opponent titles remain, and blank or equivalent labels are suppressed using case/whitespace normalization. Both data queries fetch the label. Two-line titles fit the quick-booking card with its time in all three densities, without increasing row height.
